## Why 001 was the one shipped

001 is a HIGH-confidence account-access hole. Registration is open, and
`/oauth/authorize` issued a `ScopeAll` code to any registered redirect URI as
soon as the browser carried the `SameSite=Lax` session cookie. One link was
enough to hand a third party read/write access to the user's training data,
Garmin health data and Garmin calendar. The fix is contained in
`internal/oauth`, and the package's own tests verify it fully: the new
regression test fails on the old code, showing a `code=` redirect to the
attacker-chosen URI. The rubric floats HIGH-confidence security above
equal-leverage bugs.

002 was close behind. It's the same gap the sibling repo just fixed, and it's
real here (the code is identical at every site), but it's a port. Its
verified reference patch is kept in `plans/002-reference.patch` so the work isn't lost.
